====================================================================================================

★ 2.1.1 相对 2.1.0 只动「壁纸磨砂」和几处代码级小毛病，v2.1 的排版与四种节日口径一个字没改。
   目录仍是 v2.1（成品 / 源码分开），版本号 2.1.0.0 → 2.1.1.0。

一、本版修的主要问题：换壁纸后磨砂仍透出上一张，拖到哪都不变

  1) 现象：另一块屏换了壁纸，本程序所在屏的磨砂底还是上一张壁纸的局部；
           把窗口拖到任何位置，透出来的都是那张旧图，直到下次「碰巧」刷新。

  2) 根因（2026-11-17 实测确认，不是 PrintWindow 抓错）
     · 本程序双屏各自设壁纸（多屏幻灯壁纸程序走 IDesktopWallpaper.SetWallpaper 逐屏设置），
       Windows 的做法是**每块屏各写一个转码文件**：Themes\Transcoded_000 / _001 / _002 …
     · 旧版 WallpaperSignature() 只读 SPI_GETDESKWALLPAPER 返回的那**一个**文件
       （TranscodedWallpaper），并拿它的修改时间 + 大小当指纹。
     · 实测四组相关度（同一时刻取样）：Transcoded_000 ↔ 屏1 壁纸 = 1.000，
       Transcoded_001 ↔ 屏2 壁纸 = 1.000，而 SPI 那个 TranscodedWallpaper 与两块屏都对不上
       （与屏2 仅 0.566）。也就是说：只换了另一块屏时，SPI 那个文件常常不更新。
     · 于是「指纹没变 → 整幅磨砂缓存不失效 → 一直是旧图」；
       只有主屏换图顺带把 SPI 那个文件也 touch 了，才会偶然刷新一次 —— 这解释了
       「上百次换图只错一次」「拖到哪都一样」。

  3) 修法（三处，互为保险）
     · 指纹改成拼「Themes 目录下所有 Transcoded* + slideshow.ini 的名称 + 修改时间 + 大小」，
       仍保留 SPI 段（老系统 / 非逐屏设壁纸时兜底）。任一块屏换图，指纹必变。
       实测指纹形如：
         slideshow.ini=…@0;TranscodedWallpaper=…@233022;Transcoded_000=…@1403760;
         Transcoded_001=…@643149;Transcoded_002=…@2833370;spi=C:\…\TranscodedWallpaper|…
     · 换图事件不再「当场重抓」：转码文件写好 ≠ 合成器已把新图贴到 WorkerW 表面。
       改为延迟 520ms，到期时再读一次指纹；若这期间又变了就再等一轮，稳定后才抓。
     · 抓取前后各读一次指纹：两次不一致（说明正处在换图过程中）则本次画面照样用，
       但**不锁定缓存**，下一次重绘会重抓 —— 避免把「新指纹 + 旧画面」锁死。
     · 另加两条兜底：120 秒无条件重抓一次（某次真空抓错也会自愈）；
       指纹取不到（"?"）时不再永不失效，每 5 秒兜底重抓一次。

  4) 怎么自证
     · 等壁纸自动换一张，看磨砂是否跟着变（本机两屏间隔 >2 分钟）；
     · 或看磨砂日志行（右键菜单 → 关于/诊断里的 WallFrost 行）：换图后会出现
       `captured(DIB) host=… sig=…`，若正处于换图中会带一句
       「[指纹在抓取期间又变了，本次不锁缓存]」。

五、修掉的一个老问题：中文皮肤「一」字贴底

  原来所有字都按「墨迹底 = 行槽底」摆，横画字（一 / 二）墨迹只有两三像素高，
  于是整条横线被顶到字高的最底部，看起来比旁边的字低一大截。
  现在改成：墨迹高不足参考字（「8」或「壹」）50% 的横画字，按**字高中心**摆放，且不再做
  1.12 倍的纵向拉伸；其余字保持原来的墨迹底对齐 + 等高压正。
  受影响的位置：底部公历行的「一月一日 / 星期一」、右侧农历列的「十一月」。

二、v2.0 唯一的功能增加：主时钟「中文皮肤」

  ① 开关：时钟管理 → 右侧「主时钟切换中/英文」按钮（英文界面下是 Main clock: Chinese / English）。
     · 不需要先在上方列表里选中主时钟，随时可点；点一下切换、点「确定」生效。
     · 配置键 MainSkin（0=原样英数皮肤 / 1=中文皮肤，默认 0）。老配置没有这个键 → 读成 0，

     · 与界面语言 Lang 完全解耦。

  ② 版式（四块，全部落在主时钟原本那一行里，模块高仍是 158，挂件整体尺寸一点没变）：

     中部偏左  时、分大字 +「·」        qiji 繁写；非整点最多 2+2 个汉字，整点多加一个「時」
                整块比居中位上移 6px、右移 20px（第六稿微调，CnBigShiftX/Y）
     下方居中  公历月日  星期  节日     橙标目 14.5、白数字墨迹 22，墨迹底沿距模块底 12px

                    干支两个字整行下压 3px（第五稿微调，其余各字原位不动）

  ③ 大字的取字规则（第三稿：时、分合计不超过 4 个汉字）

       · 整点三字（拾壹時、貳拾時、貳壹時…）：FCnBig3 墨迹 80，不加空格
       · 整点四字：FCnBig 常态 70
       · 字号变大后整块按「墨迹」宽度重新居中（见 ⑧ 的 CnBigLsbFix）

       · 用原先右列/底部那个橙色点（思源宋 Bold、墨迹 10px、取主题橙 Acc），

     这是字库本身的差异，不是装配问题：旧字库 qiji-combo 里各字墨迹高并不一样
     （陸 80.1% em、壹 75.3%、貳 71.5%、叁 67.6%、丙 66.7%、農 85.4%），

       ① 换库（2026-11-15 第四次修订）：整套汉字改由 qiji-fallback 出字，
          那一版各字收在 66.1%~72.0%，陸 72.0 / 壹 68.8 只差 4.6%，高矮问题在源头上基本消掉；
       ② 仍有发丝级残差，所以保留纵向归一：每个字按「壹」的墨迹高对齐（只动 Y、不改字距），
          fallback 下变形量只有 2%~5%（限幅 ±12% 根本碰不到），肉眼看不出来。
     大字与右侧三列用的是同一套归一逻辑。

  ⑩ 日历标题的农历月份（第六稿新增）

     标题次行原来只有「丙午年」，现在后面加该月的农历月名，中间空一个全角空格，字号字体不变。
     · 取法是「这个公历月里第一个农历初一所落的农历月」（CalMonthModel.LunarMon）；该月跨到
       下个月才见初一的话，取月中 15 日所在的那个农历月，所以不会出现空着不显示的情况。
     · 逐字画：子集里没有全角空格 U+3000（song-reg / song-bold / qiji-sub 三套都没有），
       整串一次交给 GDI+ 会在空格处断行（只画出「丙午年　十」），所以留空用「年」字的宽度，
       月份一个一个字排。闰月显示「闰五月」。
     · 农历月名一律用数字（正 / 二 … 十 / 十一 / 十二），不再写「冬月 / 腊月」——这样左2列
       能显示「十一月廿八日」，与公历侧的数字月一致。副作用：除夕那天的左2列从
       「臘月廿九日」变成「十二月廿九日」，日历格里腊月初一也从「腊月」变「十二月」。
       想回到传统称呼，改 Calendar.cs 里 Mn 数组的最后两项即可。

  ⑪ 雪白样式的橙色（第七稿）

     橙色在 Pal.Make 里是 P.Acc 一个字段，全程序（中文皮肤标目、英文皮肤标目、日历卡、弹窗、
     秒表/倒计时）都取它，所以改一处就全套跟着变：
        碳灰 / 藏青   P.Acc = 255,136,0（不动）
         雪白          P.Acc = 200,96,0（第七稿从 255,136,0 压暗，246 的乳白底上不再发飘）
     「除夕/春节/元宵」那三处红仍是 RGB(216,0,0)，不走这个橙色。
     唯一例外是英文皮肤里「当日星期」用的 AccBright（214,110,0），它是高亮态、不是标目橙，
     保持原样；要一起压暗改 Main.cs 里 style==1 分支的 AccBright 一行即可。
