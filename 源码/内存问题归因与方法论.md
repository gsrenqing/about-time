# 内存占用与释放问题归因与方法论

> 项目：About Time 桌面时钟挂件（C# WinForms，.NET 4.x，csc 命令行编译）
> 版本跨度：1.6 → 1.8.4（2026-11）；实测从 123MB 压到 ~53MB（用户真实配置）
> 用途：长驻桌面程序（挂件/托盘/小组件类）内存治理的可复用参考。

---

## 0. 结论先行

| 版本 | 症状/动作 | 私有内存（GC 后稳态） |
|------|-----------|----------------------|
| 1.6 | 用户报 90M+ | ~90MB |
| 1.8.0 | 实机采样 | 123.0MB（WS 147.6）——一条水平线，是基线高不是泄漏 |
| 1.8.1 | 双重解析全表改懒加载 + geo 定向扫描 | 50.4MB（WS 70.1） |
| 1.8.3 | 用户实测"又顶到 80 多 M" | ~80MB（搜过城市 +13MB 常驻 + LOH 碎片垫高） |
| 1.8.4 | 大表闲置自动卸载 + 整幅抓图告别 LOH | **53.1MB**，长时间运行平直 |

四条根因，按危害排序：
1. **同一数据被两处解析**（世界城市表 ×2，~75MB 托管）；
2. **懒加载只做了一半**：没搜过不加载，但搜过一次终身常驻（+13MB）；
3. **整幅抓图 31MB 落托管大对象堆（LOH）**：壁纸轮播反复分配 → 碎片垫高私有内存；
4. **自检与实机口径不符**：自检进程在真实路径之前 return，数字全部偏乐观。

---

## 1. 方法论：排查顺序（比任何单个修复都重要）

### 第一步：分清「泄漏」还是「基线高」
对**正在运行的真实实例**连续采样 90 秒：私有内存 / WS / 托管堆 / GC 代数 / GDI 对象 / 线程数。
- 一条水平线 + GC 代数不涨 → **基线高**，去找"启动即干了什么"；
- 缓慢爬升 → 真泄漏，按分配路径追。
本例是前者：123MB 平直 84 秒，句柄 399 稳定。

### 第二步：分阶段探针，量"每一段留下多少"
`--selftest=mem` 在真实配置、真实运行路径上打点：

```
S0 进程起步                 → 空进程底
S1 数据表加载 + 窗口构造    → 静态/构造期分配
S2 首帧 + 磨砂整幅抓取后    → 渲染首帧代价
T+10s..T+180s（真实 OnTick）→ 运行是否平直、壁纸轮换是否垫高
S4 idle N 秒 + GC.Collect   → 稳态（必须报 GC 后）
S4 10 轮渲染 + GC 后        → 渲染路径是否留东西（S4−S2 应 ≈0）
S2b/S2c（world=1）          → 大表「加载 → 卸载」的进出（1.8.4 增）
```

每行都同时记 Private（任务管理器「内存」的近亲）、WS、托管堆、GC 代数、GDI/USER 对象。
**口径教训**：自检 63MB 与实机 110MB 都"对"，但量的不是一回事——自检在数据表加载前就
return 了。凡是内存数字，一律：真实配置 + 真实路径 + GC 后稳态 + 运行 N 秒是否平直。

### 第三步：按"谁在启动时干了大事"逐段归因
托管堆 S1=41MB 而首屏根本不需要那张表 → 顺藤摸到两处无条件解析同一文件。

## 2. 坑点与解法

### 坑 1：同一数据多处解析（~75MB，1.8.1 主案）
`TimeZoneMatcher` 静态构造解析 worldcities3.txt（5.5 万行）；`CityDb.BuildGeo` 又把
同一文件建两套索引，只为给滚屏行补 "Seattle·WA·USA"。**首屏根本不需要它们。**

解法：
- 全表改 `EnsureWorld()` 懒加载（带锁，后台预热线程与 UI 线程同时到也不重复加载）；
- geo 改 `GeoFind(en, tz)` 定向扫描 + 小缓存（每城市 ~0.1s，"查不到"也缓存防抖动；
  ≥6 个城市才回退全量索引）。

**规矩**：启动只载首屏数据；一处数据一个解析器；删掉一切"预防性预热"。

### 坑 2：懒加载只做一半——搜过一次终身常驻（+13MB，1.8.4）
懒加载解决了"没搜过也背着"，但用户测一次"添加地点"后表就终身驻留——80 多 M 的差值
正是它。解法：记录 `_worldUsedUtc`，`TrimIfIdle()` 在闲置 ≥10 分钟时整表释放（双检锁，
卸载后恰好有搜索进来会重新加载）；OnTick 每分钟查一次（无表时是一次布尔判断，零成本）。
代价：卸载后再搜要重新解析 1~2 秒，仅一次——与首次懒加载等价。

### 坑 3：31MB 整幅抓图进 LOH → 碎片垫高 10~20MB（1.8.4）
换壁纸要整幅 PrintWindow。旧实现 `new Bitmap(ww, wh)` 接结果，31MB 落 LOH；
壁纸轮播每换一张分配/释放一次，长跑碎片把私有内存垫高十几 MB。
解法：CreateDIBSection 原生抓取 → StretchBlt 缩到 1/4 → DeleteObject 立即归还，
托管堆全程零压力（详见《磨砂效果问题归因与方法论》2.4/2.5）。

**规矩**：凡 >85KB（LOH 阈值）且**反复分配**的对象，走原生内存或复用缓冲；
一次性大对象如果只出现一两次，托管也可以，但要确认"用完即还"。

### 坑 4：每秒帧路径的持续分配（1.8.1 前身）
PaintFrame/RenderStatic 每次都 new 中间位图。解法：复用缓冲（staticLayer/calBuf/
frostBmp 缓存 + dirty 标记），S4−S2=0 验证渲染路径零残留。
**验证口径**：探针跑 10 轮渲染 + GC 后与首帧比，差值必须 ≈0。

### 坑 5：缓存留旧不留新（1.8.2/1.8.3 的内存侧）
磨砂缩略缓存只判"句柄+尺寸"永不失效 → 不但画面错误，也让旧壁纸的 31MB 派生数据
无处释放。修画面 bug 的同一刀（指纹判据）同时把释放链路打通了——**缓存失效和内存释放
是同一个问题的两面**。

### 坑 6：弹出层缓存的生命周期（1.8.3）
弹窗磨砂缓存 key=位置+尺寸+样式+缩放+透明度，挪一步换一块；主窗 FrostInvalidate
时联动作废。弹窗寿命短（几秒），不做独立壁纸轮询——**缓存策略要匹配对象生命周期**。

### 坑 7：换壁纸的瞬时峰值（已知、接受）
整幅抓取瞬间仍有 ~31MB 原生分配（DeleteObject 立即归还）+ 一次降采样。
托管的 quarter ~1.9MB 反复分配属同尺寸循环，LOH 空闲链表可复用，实测平直。

### 坑 8：GDI/USER 对象计数也要看
S0 起步 GDI=3/USER=5，稳态 GDI=30/USER=34，长跑不变 → 无 GDI 泄漏。
内存排查时把 GDI/USER 计数放进探针，能一眼排除"位图/DC 没还"这类本机资源泄漏
（它们不体现在托管堆上）。

## 3. 探针工具（已内置，可复用）

```
--selftest=mem;<日志>[;steps=N][;idle=秒][;world=1]
  分阶段打点；idle=N 让真实 OnTick 跑 N 秒；world=1 演示大表加载/卸载进出。
ABOUTTIME_ROOT 环境变量把配置根指到测试键值（隔离用户配置，防测试根污染视觉/内存指标）。
```

实测样例（用户真实配置：520×498、磨砂开、3 世界城市、日历弹出）：

```
S1 数据表+窗口构造        Private=51.9MB  托管堆=14.9
S2 首帧+整幅抓取          Private=66.9MB  托管堆=18.2
S2b 世界全表加载后        Private=64.4MB  托管堆=15.7   ← 搜过城市 +11MB
S2c 闲置卸载后            Private=53.3MB  托管堆= 4.6   ← 10 分钟后自动回落
S4 idle 60s + GC 后       Private=53.1MB  托管堆= 4.6
S4 10 轮渲染 + GC 后      Private=53.2MB  托管堆= 4.6   ← 渲染路径零残留
```

预期给用户：任务管理器「内存」50~65MB；搜过城市后短暂 +11MB，10 分钟后自动回落。

## 4. 可复用检查清单

**排查**
- [ ] 先对真实实例采样 90 秒，分清泄漏（爬升）还是基线高（水平线）；
- [ ] 数字一律：真实配置 + 真实路径 + GC 后稳态 + 运行 N 秒平直性，四件套齐才算数；
- [ ] 分阶段探针逐段量，别只量一个总数；
- [ ] 同时看托管堆、GDI/USER 对象、线程/句柄数。

**修复**
- [ ] 启动只载首屏数据；一处数据一个解析器；删掉预防性预热；
- [ ] 懒加载要配"闲置卸载"，否则用一次就终身常驻；
- [ ] >85KB 且反复分配的对象走原生内存或复用缓冲；缓存判据带内容指纹；
- [ ] 缓存策略匹配对象生命周期（常驻/弹层/一次性各不同）；
- [ ] 每段失效逻辑要同时释放派生数据（画面失效 = 内存释放）。

**验收**
- [ ] S4−S2 ≈ 0（渲染路径零残留）；
- [ ] 长跑（≥3 分钟，覆盖壁纸/轮播等周期事件）平直；
- [ ] 把"预期给用户的任务管理器读数"写进 README，下次有对照基线；
- [ ] 测试环境改动（时间戳/指纹/配置根）必须还原。
