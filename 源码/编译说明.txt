改代码前请先读（踩过的坑，别重踩）：
  · 右键菜单必须是常驻单例（字段 menu），只在 OnFormClosing 里 Dispose。
    在 ContextMenuStrip.Closed 回调里 Dispose 会抛「无法访问已释放的对象。对象名:
    "ContextMenuStrip"」——WinForms 的菜单消息晚于 Closed 事件到达。
  · 层级判据只能是「紧贴最高的那个桌面层窗口」（Widget.cs::KeepAboveDesktop）。写成
    「下方窗口是不是 WorkerW」会被 Win+D 提到最上层的新 WorkerW 骗过；写成「高于桌面层」
    又会让被点击抬起的挂件不再归位。2026-11-10 起改成「贴住自己下方最靠下的普通窗口
    之下」，一个普通窗口都没有时退回旧判据；普通窗口的判定见 IsNormalWindow，
    必须排除 WS_EX_TOOLWINDOW，否则别的桌面挂件会把本挂件压到壁纸下面。
  · UpdateLayeredWindow 推像素不能用 Graphics.FromImage(bmp).GetHdc()：那条路返回
    True、GetLastError=0，窗口尺寸 / LAYERED 都对，但屏幕上一个像素都画不出来。
    必须 CreateDIBSection（32bpp BI_RGB、自顶向下）+ new Bitmap(w,h,w*4,
    Format32bppPArgb, bits) + Graphics 画完再 DrawImageUnscaled 整块拷进 DIB，最后用
    DIB 的 DC 推（见 Widget.PaintCalWindowLayer / CreateCalSurface，主窗同款）。
  · 分层窗口和右键菜单只能在屏幕可见时抓屏：被别的窗口挡住时抓到的是遮挡物，
    会误判成「弹出窗没跟随」。抓前先 Win+D 或最小化挡路的窗口。
  · PushLayered 用缓存屏幕 DC（字段 screenDC + ScreenDC()），只在 OnFormClosing 释放。
  · 内嵌的 aura.ttf 缺「廿」U+5344、缺「〇」「卅」、缺藏文、无半角「·」：
    农历/藏历日号走系统宋体（MakeLunFont），中文和英文界面都必须用它，否则英文界面缺「廿」。
  · 日历固定 6 行 42 格：早期按需 5/6 行会让 cellH 在 83.2↔69.3 之间跳变，视觉上手感很怪。
  · 标题居中不能用 Ui.DrawCenter（它按墨迹居中会偏），要用 Ui.DrawAt 按字框左上定位。
  · 日号字号给到 26 时墨迹 32px，会和农历撞在一起；24 时墨迹 30px、农历 32px 在 69px 格内还有余量。
  · 本机 powershell.exe 不在 PATH；.ps1 用 & "…路径" 直接跑

一、新增「倒计时 / 秒表」模块（Timer.cs，约 570 行）
  · 模块高 40px，排在统一模块序列里（TimerPos 决定位置），与主时钟 / 世界时间 / 日历共用
    拖拽、右键菜单、透明度、缩放、主题。
  · 左侧标签「倒计时」，右侧标签「秒表」，点标签切态；两条发丝线把左右标签与中段隔开。
  · 倒计时：🔊（响闹开关）→ ■（停止）→ ▶（起跑），右侧三格输入（时/分/秒）。
    格子之间用冒号隔开，**不再写「时/分/秒」小字**（1.4 定稿去掉标注，格子因此加宽）。
    输入规则：点格进入该格（焦点格描橙框），键盘逐格两位——时格敲 1 位即自动跳分格，
    分/秒格敲满 2 位自动跳下一格，超过 59 按重新输入处理；Backspace 清当前格，Enter 起跑，
    Esc 退焦点。空值是 -1，CdTotalSec() 把 -1 当 0，避免算出负数。
    运行态：数字走七段管自绘（3:41:07），■ 亮橙、▶ 压暗；到点态停在 0:00:00 并闪橙，
    同时弹「时间已到」小窗（320×152，带一段提示音，可用 ■ 或 ▶ 回输入态）。
  · 秒表：■ / ❚❚ / ▶，右侧 0'00'000（分'秒'毫秒）。▶ 起跑、❚❚ 暂停（数字冻结）、
    ■ 停止归零；满值 59'59'999 停住转橙（SwState=3）。
  · 响闹用 winmm.PlaySound(SND_MEMORY|SND_ASYNC|SND_NODEFAULT) 播内嵌 wav：
    alarm1.wav 988Hz、alarm2.wav 783Hz，各 0.42s 音 + 0.18s 静默 ×2，22.05kHz 单声道 16bit。
    资源缺失时静默，不抛异常。
  · 计时器全逻辑自检：AboutTime.exe --selftest=tm;<日志路径>
    （键盘输入 1:23:45 → total=5025、Enter 起跑、■ 回输入态、到点判定、秒表跑/暂停/归零、
     秒表态忽略数字、命中框与按钮逐项校验）

     应用窗口 —— 这就是需求里「仅针对壁纸层」的物理保证。
  3) HasContent 24×24 抽检：整片纯黑或纯白判失败（远程桌面、壁纸引擎接管等场景会这样）。
  4) 1/4 降采样 → 两遍可分离盒式模糊（半径 10*scale，钳 ≥2）→ HighQualityBilinear 回放。
  5) LevelToMean(back, target)：把模糊图的平均亮度平移进该主题的「可读窗口」
     （碳灰 86 / 藏青 82 / 雪白 198，只加常数、偏移钳 ±60，纹理起伏原样保留），见 12.4 / 12.13。
  6) 按主题压一层很淡的色：碳灰 (42,20,20,22)、藏青 (78,20,32,60)、雪白 (58,246,246,248)。
  7) 结果缓存进 frostBmp，只在「挪动窗口 / 换主题 / 换壁纸 / 换 DPI / 松手」时置脏重抓；
     稳态零成本（不涉及系统级 acrylic / DwmEnableBlurBehindWindow —— 那套与逐像素 alpha
     分层窗口互斥，本程序用的是 UpdateLayeredWindow，走不了那条路）。

12.4 磨砂色为什么先拉亮度再压色（三次返工的结论）
  · 第一版只做「压主题色」alpha 150：暗壁纸上整个卡片近乎纯黑，完全看不出磨砂。
  · 第二版把 alpha 调到 78/96：亮蓝天壁纸把碳灰卡片冲成浅灰，白字发飘。
  · 第三版（用户实测反馈②之后的定案）把亮度拉到 118 再压固定 145~150 的色 ——
    字是看清了，但对比被压平、alpha 又太重，用户实测的观感是「开了磨砂只是背景更发白，
    任何透明度下都看不到壁纸被模糊」。也就是说：虚化被自己的压色吃掉了。
  · 第四版（当前定案，见 12.13）：
      目标亮度改按主题给 —— 碳灰 86 / 藏青 82 / 雪白 198（只加常数、钳 ±60，纹理不动）；
      压色 alpha 降到 碳灰 42 / 藏青 78 / 雪白 58。
    这样既保住文字可读的亮度窗口，又把对比留给壁纸，磨砂才「看得出是糊的」。
  · 三个主题的实机截图：v16_13 / v16_14 / v16_15（旧压色）、
    v16_29 / v16_32 / v16_33（新压色），日志里带 off / mean / tint 现场值。

12.5 语言与时区自判（这里修出一个真 BUG）
  需求：中文系统自动中文版、非中文系统自动英文版；英文版日历默认不显示农历（可手动开）；
  系统时区在中国则默认显示中国节日；干支计时默认开（英文版同样开）。
  · 第一版把这些推导写在「读注册表」的 if (k != null) 里面。自检一跑就露了：
    整条 HKCU\Software\AboutTime 子键不存在（真正的第一次运行）时，k == null，那段代码根本不执行，
    生效的是字段初值 —— Lang="zh"、CalLunar=true、CalCC="auto"。
    也就是说「英文系统首启仍是中文版」。
  · 改为：进函数先算 defLang（CultureInfo.CurrentUICulture.TwoLetterISOLanguageName），
    读完注册表后按 hadKey 判断，没有键就显式推导：
        Lang = defLang；CalLunar = (defLang != "en")；CalCC = IsChinaZone() ? "CN" : "auto"；GzOn = true。
  · 证据（--selftest=detect，配合环境变量 ABOUTTIME_ROOT 指到一个不存在的子键，只读不写）：
        v16_18_自检_无键启动_中文系统.txt  → Lang=zh、农历开、CalCC=CN、干支开
        v16_19_自检_无键启动_英文系统.txt  → Lang=en、农历关、CalCC=CN（时区在中国）、干支开
    全程没有写过用户真实的 HKCU\Software\AboutTime（跑完核对过 Style/Opacity/Lang/CalLunar/CalCC/GzOn 未变）。

12.7 菜单「第一次悬停卡顿」——先量化再改，结果和最初的推断不一样
  最初推断是「ToolStripDropDown 的下拉窗口要等第一次 Show 才 CreateWindow + 量布局」。
  于是加了 --selftest=menu 分支来量，实测（本机）：
        冷建 9 个下拉窗口           12～17ms
        子菜单第一次 Show             8～9ms     （预热后 6～9ms，差别在噪声内）
        每次右键重建整份菜单          0.3～0.5ms
        推一帧全卡逐像素 blit         0.9ms      （16ms 定时器占空约 6%）
        重做静态层 RenderStatic       2.7ms
  结论：单纯的下拉窗口创建不足以造成可感知卡顿。所以真正处理的是三件事：
    ① BuildMenu 开头由 Clear() 改成逐个 RemoveAt + Dispose()。
       旧写法只把条目从集合里摘掉、对象留着，长期使用会一直累积 ToolStripItem（GC 抖动来源之一）。
    ② WarmMenu()：ShowMenu 里 BuildMenu 之后立刻 menu.CreateControl() + 递归 WarmItems()，
       把每层下拉窗口先建出来（只做一次，menuWarmed 标记）。首次悬停可测开销 17ms → 9ms。
    ③ OnTick 开头：菜单开着时直接 return，不推帧 —— 把 16ms 一拍的定时器让给下拉窗口。
  这三条一起上，本机能测到的「首次悬停」开销降到约一半。若实机上仍有明显卡顿，
  需要用户提供更具体的触发场景（哪一项、什么时机、卡多久），因为现有测量手段已经量不出更大头。

12.8 干支行逐字绘制（字距 3px 与冒号掉字）
  · 1.5 遗留：整串一次 DrawString 时，字距由点阵字库自带，「叁→刻」实测只有 2px。
  · 改为逐字绘制：SegWidth(Font,string) 累加「Ui.Ink 宽度 + TimeGap(3px)」；
    DrawSeg 每个字按**墨迹左沿**定位（不是排布原点），所以 3px 是净间隙。
  · 冒号：ColonW 由 14 → 16，冒号两块 4×4 手绘、左右各留 6px（点阵字库的 ':' 在 26px 字号下不可见）。
  · 实测列区间（v16_10 3× 放大核对）：亥 18..38、初 43..65、冒号 73..76、叁 83..107、刻 112..134，
    间隙 4 / 7 / 6 / 4，全部 ≥3px；冒号左右 7:6（差 1px，可接受）。

12.12 第二轮：用户实测报上来的两个真 BUG（根因 + 修法 + 怎么回归）

  这一节是 1.6 出第一版成品、交付之后，用户在真机上点出来的两个缺陷。
  两个都是真 BUG，不是误报；共同点是「我上一轮的出图路线恰好绕开了它们」。

  12.12.1 切英文版后，时钟管理弹窗仍是中文

    现象：右键菜单切到英文、TIMER/STOPWATCH 与日历都变英文了，唯独「时钟管理」弹窗整窗中文。
    根因：语言切换走 WidgetForm.SetLang(lang)，它只做了两件事：
            S.Lang = lang;  rows[i].MDirty = true;
          而四个弹窗（ClockManagerDialog / 城市选择 / 时区选择 / 手动时区）里的每一句文案
          走的是 Support.cs 里的 L.B(zh, en)：
            static class L { public static string B(string zh, string en)
                             { return Settings.CurrentLang == "en" ? en : zh; } }
          也就是说它们看的是 Settings.CurrentLang，而 CurrentLang 整个工程里只在
          Settings.Load() 里被赋过一次值 —— 运行期切语言根本没碰它。S.Lang 换了，弹窗不知情。
    为什么上一轮没抓到：给文档出图用的是 --shot=…;lang=en，那条路线调 SetPreviewLang()，
          而 SetPreviewLang 里写的是 S.Lang = lang; Settings.CurrentLang = lang;（两个都设）。
          预览捷径把产品路径上的这条缝正好补上了，于是「出图全英文、用户实机全中文」。
    修法：SetLang() 里补一行 Settings.CurrentLang = lang;（与 SetPreviewLang 保持一致），
          并写明注释「只改 S.Lang 不够 —— 四个弹窗全走 CurrentLang」。
    回归：新增 --selftest=lang;<前缀>，实现是 WidgetForm.LangSwitchSelfTest(string pngPrefix)：
            SetLang("en") → 构造 ClockManagerDialog → 读 .Text / 列表首行 / 提示首行 → 存 png → Dispose
            → SetLang("zh") → 再构造一次同样读一遍 → 存 png
          关键点是它**走产品自己的 SetLang**，不走预览捷径 —— 这类「预览和产品两条路」的 BUG，
          自检必须从产品入口进。
          实跑（v16_23_自检_切语言后时钟管理.txt）：
            切到 en 后 CurrentLang = en，S.Lang = en
            时钟管理弹窗标题 = clocks configuration
            第 1 行 = Countdown / Stopwatch
            提示首行 = The main clock sits on top by default and can be moved up or down; …
            切回 zh 后标题 = 时钟管理

  12.12.2 开磨砂后「背景透明度」失效

    现象：勾上「背景磨砂效果（仅壁纸层）」之后，右键里的「背景透明度」怎么拉都看不出变化。
    根因：磨砂底图 fb 是整块不透明的 —— 模糊后还要再按主题压色（LevelToMean + tint），
          像素 alpha 全是 255；绘制时直接
            g.DrawImage(fb, 0, 0, w, h);
          透明度设置压根没参与。普通（非磨砂）模式下卡片底按 S.Opacity 算 alpha，
          所以只有磨砂这一条路径把透明度吃掉了。
    修法：贴磨砂层时用 ColorMatrix 把 alpha 整体缩放：
            float op = S.Opacity / 100f;（钳 0.10 ~ 1.0）
            ColorMatrix 第 4 列 alpha 行写 op，其余保持单位阵；
            ia.SetColorMatrix(cm, ColorMatrixFlag.Default, ColorAdjustType.Bitmap);
            g.DrawImage(fb, new Rectangle(0,0,(int)w,(int)h), 0, 0, fb.Width, fb.Height,
                        GraphicsUnit.Pixel, ia);
          文字照原样随后绘制、仍是全不透明 —— 半透明背景 + 实心文字，正是分层窗口该有的样子。
          必须用这个「整数 Rectangle + srcX/srcY/srcW/srcH + GraphicsUnit + ImageAttributes」重载；
          DrawImage(Image, RectangleF, RectangleF, GraphicsUnit, ImageAttributes) 在 .NET 里不存在，
          写成 RectangleF 会 CS1502 / CS1503（已实测报错原文：参数 2: 无法从 RectangleF 转换为 float）。
    回归：新增 WidgetForm.SetPreviewOpacity(int)（设 S.Opacity → 重算 Pal → 清静态层 → RenderStatic + PaintFrame），
          磨砂自检参数扩成 --selftest=blur;<前缀>[;dark|white|navy][;op=NN]，
          解析处不再只看 bparts[1] 当主题，改为遍历所有段：主题段认 dark/white/navy，op=NN 认透明度。
          实机三档（v16_24 / v16_26 / v16_25）：
            op=100 → 不透明烟色玻璃，壁纸只在边缘微透            （326 KB）
            op=70  → 用户现值：岩壁轮廓透出，白字仍清晰          （708 KB）
            op=40  → 壁纸大面积透出，磨砂只剩薄雾                （807 KB）
          三张真实桌面抓图的体积差异本身就说明不是同一张图重存。

  12.12.3 顺带踩到的两个工程坑（写下来免得下次再犯）

    · 抓磨砂实机图会被别的窗口挡住。--selftest=blur 用 CopyFromScreen 抓真桌面，
      如果此刻前台是别的程序（比如 IDE、聊天窗），抓到的是那个窗口，磨砂图就废了。
      修法：WidgetForm.ForceTopForTest() —— TopMost = true 之后再来一发
      SetWindowPos(Handle, HWND_TOPMOST, …, SWP_NOSIZE|SWP_NOMOVE|SWP_SHOWWINDOW) + SetForegroundWindow，
      只用于抓图，Dispose 即消失，不影响产品行为（产品本身仍然是「总在最前关掉时用 z-order 锚点」）。
      判据：三张图若字节数完全一样，基本就是三张都抓到了同一个前台窗口，要重抓。
      后来实测发现 ForceTopForTest **不总管用**（对方窗口自己是 TopMost、前台锁被占时压不住），
      抓到聊天窗两次之后，最终改法见 12.13.2：不再抢 z-order，改成「藏挂件 → 抓真桌面 → 叠合成帧」。

    · 预览/自检路线会把当时的预览状态写回注册表，进而改掉用户配置。
      本轮我出图跑完发现 HKCU\Software\AboutTime 的 Style 由 dark 变 navy、Opacity 70 变 80、
      TimerAlarm 1 变 0、X/Y 68/52 变 45/88 —— 都是预览路线里的 SaveSettings 与窗口关闭时落的位置。
      已按备份 reg_backup.txt 逐项改回，并给出一条硬规矩：
        凡是出图/自检，先 $env:ABOUTTIME_ROOT = 'Software\AboutTimeTest'（Settings.RootPath 会读这个环境变量），
        跑完 Remove-Item 掉临时子键，再核对真实键六项没变。
      这条规矩比事后恢复靠谱：v16_23 起的所有证据图都是这么跑的。
      顺带一提，Settings.RootPath 与 static Settings() 读环境变量这套，是 12.6 为「无键启动」自检加的，
      这次正好复用成了「测试配置隔离」。

12.13 第三轮：磨砂「只发白、看不见模糊」（用户实测反馈③）
  12.13.1 根因与修法
    · 用户原话：「磨砂效果打开与关闭的区别只是背景图是否更发白，无论任何透明度下，
      打开磨砂效果均看不到任何被遮挡的壁纸变模糊。」
    · 根因不是模糊没做，而是模糊被压色盖住了：WallpaperFrost 里 LevelToMean(back, 118)
      把整幅模糊图的平均亮度硬拉到 118，对比被压平；随后再叠 (150,20,20,22) 这种 alpha 145~150
      的主题色，壁纸纹理只剩一成多。亮度拉平 + 重压色的组合，看起来就是「一层白纱」。
    · 修法（WallpaperFrost.Grab 尾部）：
        目标亮度按主题给：碳灰 86 / 藏青 82 / 雪白 198（只加常数，偏移钳 ±60，纹理原样保留）；
        压色 alpha 降到 42 / 78 / 58（藏青第一版用 46 辨识度不够，实机看图后加到 78）。
      新增只读的 MeanLevel(Bitmap)（只量均值，供日志与前后对照），
      LevelToMean 的日志由「mean= off=」改为 append 形式，最终一行形如：
        off=-51 (137->86) mean=137->88 tint=42 ok host=WorkerW hostRect=0,0,3640x2129 rect=1020,80,520x498
    · 三个主题的定案值（style 0/1/2）：target 86/198/82，tint ARGB 42/(58)/(78)。

  12.13.2 出图怎么保证「真的是屏幕上看到的样子」
    · 老办法 CopyFromScreen 直接抓屏，前台只要不是挂件（聊天客户端、IDE）就抓到那个窗口；
      先加 ForceTopForTest()（TopMost + SetWindowPos HWND_TOPMOST + SetForegroundWindow）仍然被挡 ——

第 13 章  1.7 变更记录（第七次修改 · 2026-11-12 · 磨砂方案返工 + 审阅 BUG 清理）

13.1 为什么 1.6 的磨砂救不回来（三份实测，都是方案层面的错）
  · 用户实测反馈（1.6 交付后）：
      ① 打开磨砂后内存占用超过 90MB；
      ② 打开磨砂看不出模糊，反而是背景（卡片）大幅变白。
  · 「变白」的量化：用 1.6 自己的 --selftest=blur 图（_comp.png 与 _bg.png 同坐标），
    在卡片左内边无文字条带（x≈2.5%、y 25%~85%）上量 2B+3G+R 亮度：
        壁纸 194.6 / 磨砂关 卡片 20.0 / 磨砂开 卡片 100.1（op=70，碳灰）
    即 +80 灰阶。根因是 LevelToMean：它把整幅糊图的平均亮度**加法平移**到定标值
    （碳灰 86），偏移钳 ±60 —— 亮壁纸（均值 130~200）压不回 86，最多减 60；
    而主题色只以 alpha 42/78/58（16%~30%）掺进来，压不住残余亮度。
    加法平移还有个副作用：暗部永远到不了黑 → 必然出雾（"一层白纱"）。
  · 「看不出模糊」的三个来源：
      a. 合成公式：1.6 在 RenderStatic 里用 ColorMatrix 把磨砂层 alpha 缩到 S.Opacity/100，
         屏幕上得到 = op×糊壁纸 + (1-op)×**清晰的桌面原图**。op=40 时 60% 的像素是清晰的，
         模糊被自己的透明度稀释 —— 这是最要命的一条，也是「无论什么透明度都看不到糊」的直接原因。
      b. 开关之间 +80 的亮度差抢走了观感，纹理消失变成次要信息。
      c. 1/4 图半径 10*scale、两遍盒式的模糊偏狠，HF 只剩 ~17%。
  · 「内存 90M+」的量化：双屏 WorkerW 是 3640×2129，PrintWindow 一次 = 3640×2129×4 ≈ 31MB
    原生位图，加上 cut / back / MeanLevel / LevelToMean 各 ~1MB 短命缓冲，每次重抓 ≈ 34MB；
    触发面：拖动松手 / 换主题 / 换缩放 / SetBlur / 置顶切换 / UserPreferenceChanged（General 类很频繁），
    全部在 UI 线程同步执行（单次 200~500ms 卡顿），堆碎片累积后 WS 冲到 90MB+。
    实测同机同壁纸：磨砂关 WS 58.0MB；1.6 磨砂开 WS 60.4MB 但 Peak 146.8MB/次，反复触发即累积。

13.2 WallpaperFrost.cs 重写（本版唯一的大改）
  · 新增整幅壁纸 1/4 缩略缓存：
      static Bitmap _wallQ; static IntPtr _host; static int _ww,_hh;
      public static void InvalidateCache();          // 只释放 ~2MB 缩略图
      static Bitmap EnsureQuarter(host, wr);         // 宿主/尺寸不变 → 直接复用
    抓取流程：PrintWindow 整幅（每个进程/每次换壁纸只做一次）→ 立即 HighQualityBilinear
    降采样到 qw×qh（(ww+3)/4，双屏 910×533 ≈ 1.9MB）→ Dispose 整幅 → 缓存。
    实测：稳态只多 ~5MB（缩略图 1.9 + 成品 1.0 + 静态层），重新裁剪一次 <10ms。
  · Grab 流程（每次重抓只做这些）：
      ① 由挂件屏幕矩形换算到 1/4 坐标（qs = qw/ww，浮点，避免整除累计误差）；
      ② 外扩 margin = 2r 并钳进缩略图范围 → 从缩略图裁出「外扩块」；
         外扩是为了消掉盒式模糊边界 clamp 造成的拖影条纹（1.6 卡片四边有一圈不自然的带）；
      ③ 两遍可分离盒式模糊，半径 r = 7*scale（1.6 是 10*scale）；
      ④ 乘法压暗：k = TargetOf(style) / MeanOf(块)，钳 0.45~1.80，就地 ScaleSmall；
      ⑤ 回放大到物理尺寸并叠主题色（a 见 13.3）；
      ⑥ 窗口压出屏幕边缘的小条用主题基色兜底（g.Clear(baseC)）。
  · 判空口径：FlatExtreme(q) 只在「均匀且极端（max-min<2 且 mean<6 或 >249）」时判失败；
    1.6 的 max-min<8 会把纯色 / 弱渐变壁纸误杀成「抓取失败 → 退回实心卡」。
  · 资源释放：PrintWindow 用的 DC 来自 Graphics.GetHdc，只用 g.ReleaseHdc 配对（1.6 的
    finally 里调了 ReleaseDC(host, dc)，语义错位且异常路径会漏 ReleaseHdc）。
  · 删除 MeanLevel / LevelToMean / Down（不再需要整图归一与单独降采样）。
  · Grab 签名变为 Grab(Rectangle, int style, double scale, double opacity)：
    透明度必须进来参与合成（见 13.3）。

13.3 合成配方（两步，Windows acrylic 的口径）
  · ① 乘法压暗：target 碳灰 78 / 藏青 72 / 雪白 195；k 钳 0.45~1.80。
        乘法只改明暗、不改相对对比：亮壁纸压下来、暗壁纸按原样留（k 上限 1.8 只做轻微提亮），
        暗部不会像加法那样被抬成雾，纹理起伏比例不变。这是与 1.6 LevelToMean 的本质区别。
  · ② 主题色收缩：out = blur×(1-a) + base×a，a 碳灰 0.66 / 藏青 0.64 / 雪白 0.52；
        base = 碳灰 (20,20,20) / 雪白 (246,246,246) / 藏青 (22,34,64)，与 Pal 的卡片底一致。
  · 「背景透明度」语义（磨砂模式）：玻璃浓度 aEff = a + (1-op)×(1-a)，op=1 → a。
    任何档位都不掺清晰桌面 —— 于是 RenderStatic 里不再需要 ColorMatrix：
        g.SetClip(RoundRect(0,0,w,h)); g.DrawImage(fb,0,0,w,h); g.ResetClip();
    普通（非磨砂）模式仍是原来的整卡半透明，行为不变。
  · 为什么不做「系统级磨砂」：DwmEnableBlurBehindWindow / DWMWA_SYSTEMBACKDROP_TYPE 与
    UpdateLayeredWindow 驱动的逐像素 alpha 分层窗互斥；SetWindowCompositionAttribute 的
    ACCENT_ENABLE_ACRYLICBLURBEHIND 在分层窗上行为未定义（整窗染色、不可控）。自抓壁纸是唯一可控路线。

13.6 本轮踩的坑
  · 中文路径经 PowerShell Start-Process -ArgumentList 传参会被截断/损坏（本次「自检不产图、
    exit=0」查了两轮，最后定位是参数里的非 ASCII 目录名）；出图/自检一律先用纯 ASCII 中转目录，

  · 同一坑的变体：`Start-Process $exe -ArgumentList '--selftest=blur;'+$t+'\x'` 不加括号会被
    PowerShell 当成多个位置参数，报 PositionalParameterNotFound 而整条命令静默失败 ——

  · C# 5（csc 4.0.30319）不支持局部函数：本想给自检写个 Luma 局部静态方法，必须提到 Program 类级。

        1.7.1 磨砂开 op50：卡片 HF 0.38，但视觉上"没糊" —— 因为卡片像素 = 0.5×糊壁纸 + 0.5×**清晰桌面**，

  · 物理约束（必须写清楚，避免以后再翻烧饼）：
        UpdateLayeredWindow 下屏幕像素 = op×本程序内容 + (1-op)×真实桌面；
        真实桌面那部分是清晰的，程序无法修改；op<100% 时它必然带清晰边缘上来。
        系统 acrylic（SetWindowCompositionAttribute / DwmEnableBlurBehindWindow）能做真模糊，
        但与分层窗的逐像素 alpha 互斥：要用它就得放弃 UpdateLayeredWindow，
        把圆角抗锯齿、逐像素透明、菜单全部改成普通窗口 + SetWindowRgn，风险远大于收益。
  · 定稿方案「雾面玻璃」：
       ① 磨砂层始终**不透明**（RenderStatic 直接整块 DrawImage，不再按 op 压 alpha）；
       ② 「背景透明度」折进颜色：t = TintOf(style) × op，
          TintOf = 碳灰 0.80 / 藏青 0.78 / 雪白 0.72（op=100% 时的主题色占比）；
          内容 = 糊壁纸×(1-t) + 主题基色×t。
          op=10% → t≈0.08，几乎只见糊壁纸（最"透"）；op=50% → t=0.40 烟色玻璃；
          op=100% → t=0.80，接近纯色卡片（100% 该有的样子）。
       ③ 数字方向单调：越大越"实"，与普通模式的「不透明度」同向 —— 1.7.0 的倒挂不再出现。

       底下的整幅图还是旧的。

      ① 第一版断言「整幅抓取 +2」，FAIL 1→2 —— 整幅计数不区分调用方：弹窗复用了主窗刚抓的

  18.2 磨砂五档：从 1.5 档到 5 档，并按「3 档 = 1.8.5 的 1 档」重排

    · 根因（WallpaperFrost.Grab）：1.8.5 的模糊是在 1/4 缩略图上做的。
      PassesFor(level) 给的是**1/4 缩略图上的半径序列**：[2] / [2,1,1] / [2,2] / [2,2,2] / [4,1]，
      等效高斯 σ 折到全分辨率约 2.00 / 2.45 / 2.83 / 3.46 / 4.12px（相差不到两个像素），
      糊完再 4× 双线性放大 —— 那层放大本身就把差异抹平了；每档半径还撞 Math.Max(1,r) 下限，
      小半径直接塌成同一个值。
      实测（op=70、碳灰、同一张壁纸，纹理保留率）：1/2/3/4/5 档 = 8% / 5% / 5% / 5% / 4%，
      1/8 结构梯度 24/21/21/19/18 —— 2、3、4 档互差 ≤3%，等于同一张图。
    · 改法：模糊搬到**全分辨率**裁剪块上。
      (1) 仍从 1/4 缩略缓存裁「卡片外扩块」（外扩 margin=(r+r2)*2），但按全分辨率重采样；
      (2) 在这块（约 560×540）上跑盒式模糊，4、5 档（r≥12）再补一遍 r/3 压盒式方肩；
      (3) 画回卡片矩形，卡片外沿落不到壁纸的地方用 ThemeBase() 基色兜底。
      BoxBlur 只糊 R/G/B（ch<3），省掉 1/4 的 alpha 分支；新增 LastBlurMs 与日志 blur=xx.xxms。
    · 标尺（用户 2026-11-13 定：「你的 1 档 = 旧版 1 档 = 新作的 3 档」）：
      全分辨率半径 3 / 5 / 8 / 13 / 20 px。3 档单个 r=8（等效内核宽 17px）= 1.8.5 的 1 档；
      r2 只在 r≥12（4、5 档）时使用，保证 3 档与旧版 1 档逐像素对等。
    · 实测（同一张壁纸、op=70 碳灰，卡片内纹理梯度，数值越大越清）：

        档位   半径     1/1 梯度   1/8 结构梯度   模糊耗时
        1      3px      0.886      5.235          4.85 ms
        2      5px      0.657      4.490          4.46 ms
        3      8px      0.478      3.474          4.61 ms

    · 根因（Main.cs / TimeZoneMatcher）：1.8.5 给城市补国家码/州省码走 GeoFind，每个城市都要

19.5  大字绘制：三段式，别让「·」顶掉一个字

  旧写法（第一版已改）：
      for (i = 0; i <= gl.Count; i++)
          if (i == dotIdx) { 记点坐标; x += dotW+hsep; continue; }
          画 gl[i] ...
  dotIdx = hs.Length = 2，于是 i=2 那一次把 gl[2]（分钟的第一位）跳过了 —— 首图
  「零時·柒」就是这个原因，CnDebug 里 glyphs=4、sumW=250 却怎么也找不到宽度问题。
  现写法：
      for (i = 0; i < hs.Length; i++) CnBigGlyph(g, ch, ref x, sx, baseline, sep, f, b, glow);  // 时
      _cnDotCx = x + dotW/2f; _cnDotCy = baseline - bigInkH/2f;
      x += dotW + hsep;
      for (i = hs.Length; i < gl.Count; i++) CnBigGlyph(...);                                  // 分
  CnBigGlyph 自己负责 save/translate/scale、按 -ink.X 与 -ink.Y 定位、推进 x 三个动作；
  第二版把 Font 也做成参数（整点两/三字要换大一号的字体），字刷与光晕依旧是入参。

19.12  第四次修订：整套汉字换用 qiji-fallback（2026-11-15 晚）

  背景（用户定位的结论，实测吻合）：
    「陸比别的字高」不是装配问题，是 qiji-combo.ttf 本身的度量缺陷。同一个 em 下
    各字墨迹高：陸 80.1%、農 85.4%、壹 75.3%、貳 71.5%、叁 67.6%、丙 66.7%，
    按同一条墨迹底沿排下来，高字必然顶出一截；当时是靠 ±12% 纵向归一硬压住的。

  做法：
    · 版面所有取自 qiji 的字（大字、右三列、「公元/年」标目旁的年份数字除外、底部节日繁体名
      等）全部改由 字体\qiji-fallback.ttf 出字。该文件 38,832,332 B / 20,971 字，
      同一套字形的另一版本，墨迹高收到 66.1%~72.0%（陸 72.0 / 壹 68.8，只差 4.6%）。
    · 字符集不动：直接读旧 qiji-sub.ttf 的 113 个码位，用这份码位向 fallback 切子集，
      逐字核过 fallback 的 cmap 全覆盖（missing 为空），含「叄」0x53C4 与「閏」0x958F。
    · 产物仍叫 fonts\qiji-sub.ttf（163,496 B，113 字），compile.rsp 一个字不用改；
      旧 combo 子集另存 fonts\qiji-sub-combo.bak（不参与编译）。
    · 「·」U+00B7 与「〇」U+3007 两个 qiji 字库都没有 → 时、分之间的点继续用思源宋 Bold 墨迹 10，
      左竖年份数字继续用思源宋；这不是遗漏，是这两个字符本来就只能这么取。
    · 归一逻辑保留（19.11 ④ 不改），但 fallback 下 sy 只在 0.96~1.04，属发丝级微调，
      限幅 0.88~1.12 碰不到。

  切片脚本（与旧版唯一的差别是源文件；注意 populate 只收 text=，误传 unicode_codepoints 会 TypeError）：
      from fontTools.ttLib import TTFont
